# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

local.vibe — a local DNS daemon that gives dev servers friendly `.vibe` names. CLI binary is `vibe` (`vibe.exe` on Windows). Single Go binary, minimal dependencies (only Cobra + `golang.org/x/sys` for Windows syscalls; rest is stdlib).

Supports macOS and Windows. Linux is stubbed out behind build tags but not wired up — see `FUTURE_PLAN.md`.

## Workflow

- **Never commit unless the user explicitly asks.** Do not auto-commit after completing a task or bundle commits into other actions.
- **Always run `vibe dev` after changes** to rebuild and restart the daemon.
- **Tests must pass before declaring a task done or pushing.** Run `go build ./... && go vet ./... && go test ./...` after any change. If a test fails — even one that looks unrelated or flaky — investigate before continuing. Do not push or open PRs over a red test suite. If a failure is genuinely flaky, re-run a few times; if it reproduces, fix it or call it out explicitly to the user before moving on.
- **Check CI on `main` periodically.** If CI is red on `main`, the next change should fix it before adding new work — don't keep stacking commits on a broken pipeline.

## Build & test

```bash
vibe dev              # rebuild binary + restart daemon (do this after every change)
go build -o vibe .    # just build
go test ./...         # run tests
go vet ./...          # lint (also runs in CI)
```

CI runs the matrix on macOS/Ubuntu/Windows against Go `stable`, plus a
`minimum-go` job that builds and tests against `go-version-file: go.mod`. The
matrix deliberately does **not** pin a version: it used to pin 1.22, and when
GitHub moved `macos-latest` to a newer image, dyld began rejecting that
toolchain's cgo-linked test binaries (`missing LC_UUID load command`) — a
failure with nothing to do with our code. The `minimum-go` job is what keeps
go.mod's declared floor honest.

`.gitattributes` pins the tree to `eol=lf`. That is not cosmetic: `SKILL.md` is
`//go:embed`-ed and installed *verbatim*, so a CRLF checkout would ship
different bytes on Windows and desynchronize the embedded copy from the
marketplace copy that `marketplace_test.go` compares byte-for-byte. Two tests in
`internal/vibeskill` enforce it. Don't "fix" a line-ending test failure by
normalizing inside the test — that hides a real artifact difference.

The daemon runs a compiled binary, not source — changes aren't picked up until rebuilt. `vibe dev` handles the full cycle and is per-OS:

- **macOS** (`cmd/dev_unix.go`): build → install to `/opt/homebrew/bin/vibe` → kill old daemon → LaunchAgent auto-restarts with new binary.
- **Windows** (`cmd/dev_windows.go`): build to `vibe.exe.tmp` → stop daemon → rename current `vibe.exe` to `vibe.exe.old.<ts>` (Windows refuses to overwrite a running .exe) → rename `.tmp` → start daemon via Scheduled Task. Stale `.old.*` files are cleaned up on the next `vibe dev` run.

## Architecture

**Request flow (macOS):** Browser → dnsmasq (*.vibe → 127.0.0.1) → pf (443 → 7443, 80 → 7999) → daemon (HTTPS or HTTP) → reverse proxy → app on target port. The pf redirect is the layer most likely to break at runtime — a VPN/firewall reloading pf flushes it — so it's re-asserted on network changes (see pf resilience below) and `vibe doctor` checks/repairs it.

**Request flow (Windows):** Browser → adapter DNS (set to 127.0.0.1) → embedded Go DNS resolver on `:53` (synthesizes A=127.0.0.1 for `*.vibe`, forwards everything else to upstream) → netsh portproxy (80→7999, 443→7443) → daemon → reverse proxy → app.

Bookmark routes either redirect (307) to an external URL or reverse-proxy to it (when `proxy=true`). HTTP requests redirect (301) to HTTPS when TLS is enabled.

**Three layers, strictly separated:**

1. **CLI commands** (`cmd/`) — Cobra commands. Know nothing about daemon internals. Use `internal/client` to talk to daemon.
2. **Client** (`internal/client/`) — HTTP wrapper. Tries Unix socket (`~/.vibe/vibe.sock`) first, falls back to TCP (`127.0.0.1:7999`).
3. **Daemon** (`internal/daemon/`) — HTTP server with embedded HTML dashboard. Core components:
   - `daemon.go` — Server struct, Start/Stop, HTTP routing by Host header (`routeRequest`), reverse proxy with `handleProxyError` recovery on upstream failure, TLS listener with cert hot-reload, optional embedded DNS resolver (Windows only)
   - `daemon_unix.go` / `daemon_windows.go` — per-OS port-holder lookup and process termination (`lsof` + SIGTERM on unix; `netstat -ano` + TerminateProcess on Windows)
   - `api.go` — REST endpoints under `/_api/` (register, deregister, update, list, health, start, stop, ready, repair, preferences). Route names validated as DNS-safe (lowercase alphanumeric + hyphens). All user input HTML-escaped in dashboard output.
   - `routes.go` — Thread-safe RouteTable (RWMutex + map), RouteType enum, atomic per-route Failure diagnostics
   - `process.go` — ProcessManager spawns/kills managed child processes; structured `StartError` with the tail of the log file on immediate crash. Per-OS spawn attrs and kill semantics live in `process_<goos>.go` (process groups + SIGTERM on darwin/linux, Job Objects + TerminateJobObject on Windows).
   - `process_alive_unix.go` / `process_alive_windows.go` — `processAlive(pid)` (signal-0 trick on unix; OpenProcess + GetExitCodeProcess on Windows).
   - `managed_exit.go` — `handleManagedExit`, the event-based replacement for the old 5s polling sweep: fired the instant a managed child exits (via `cmd.Wait` for spawned children, per-OS PID-exit watchers for adopted ones) and flips the route to not-running, seeding a failure only for *unexpected* deaths (intentional stops set `Running=false` first). Also `watchTrackedPID`, which removes a PID-tracked route when its external process dies.
   - `managed_timers.go` — per-route lifecycle timers, armed/canceled via `RouteTable` add/remove hooks (`SetHooks`) so every register/start/stop/deregister path is covered from one place: a one-shot `time.AfterFunc` for TTL expiry, and a self-rescheduling idle timer that reads the route's last activity (recorded cheaply on the request hot path) and auto-stops it past `idle_timeout`. No periodic sweep.
   - `process_wait_{darwin,linux,other}.go` — `watchPIDExit(pid, fn)`: blocks until a PID exits with no polling (kqueue `NOTE_EXIT` on darwin, pidfd + poll on linux, no-op elsewhere). Used for adopted and PID-tracked processes that have no `*exec.Cmd` to `Wait` on.
   - `autostart.go` (+ `autostart_<unix|windows>.go`) — On-demand recovery for managed routes that come up stopped after a daemon restart. On startup and on each request to a stopped managed route: re-**adopt** a surviving child (unix — managed children outlive the daemon; verified by checking the route's registered port is held by a member of the child's process group), else **auto-spawn** it and show the reconnecting page, else fall back to the start page. Adoption registers the PID with `ProcessManager.Adopt` so Stop/Deregister can still kill it. Gated by `daemon.autostart` (default on); adoption always runs. No-op adoption on Windows (Job Objects kill children on daemon exit).
   - `persistence.go` — Saves/loads sticky, managed, and bookmark routes to `~/.vibe/routes.json`
   - `dashboard.go` — Embedded HTML dashboard with modal UI for adding/editing routes
   - `startpage.go` — "Not running" page for stopped managed routes with Start button; surfaces recovery hints as a one-click "Kill PID X and Retry"
   - `repairpage.go` — "Reconnecting..." page shown when a route's port goes dark; polls `/_api/routes/{name}/repair` to auto-discover the new port
   - `log_scan.go` — regex patterns for extracting recovery hints (orphan PID, EADDRINUSE) from failed process log tails
   - `port_discover.go` + `port_discover_unix.go` / `port_discover_windows.go` — finds a managed route's real listening port via `lsof` on the process group (unix) or by enumerating Job Object members and parsing `netstat -ano` (Windows), plus a log-tail regex fallback
   - `proxy_bookmark.go` — reverse-proxy for bookmark routes with `proxy=true` (landing path redirect, Location/cookie rewrites, X-Forwarded-For suppression)
   - `sync_config.go` — re-reads `vibe.json` from a managed route's `Dir` on each `Start` so edits to `cmd`, `oauth_callback_port`, or `reserve_ports` take effect without re-registering
   - `oauth_bridge.go` — per-route localhost OAuth callback listeners (see `oauth_callback_port`); 307-forward `?code=...` from `localhost:N` to `https://name.vibe/...` so OAuth providers that require a localhost redirect URI work without leaving the .vibe origin. `oauthEnvForRoute` (in `oauth_worktree.go`) injects `AUTH_URL`/`NEXTAUTH_URL` = `http://localhost:N` at spawn via `ProcessManager.SetEnvHook`, so frameworks that would otherwise derive the redirect URI from the listening port (Auth.js v5) match the provider registration. Env injection rather than a `.env` edit is load-bearing: Node loaders don't override real env vars, so it survives a regenerated `.env` (`vercel env pull`)
   - `theme.go` — Shared CSS/HTML head (Geist fonts, Vercel-inspired dark theme)
   - `setup_md.go` — Markdown setup guide served at `/setup.md`
   - `serviceworker.go` + `sw.js` — Browser-resident offline fallback for `local.vibe`. The dashboard registers `/sw.js`; when the daemon/redirect is unreachable the worker serves a cached "redirect is down — run `vibe doctor --fix`" page (races the real fetch against a 1s timeout, then probes the direct HTTP port to distinguish "redirect down" from "daemon down"). The fallback page arms its auto-reload **before** awaiting that probe and bounds the probe at 2s: a VPN kill-switch that accepts the connection and forwards nothing — the exact case this page explains — would otherwise hang it forever with the retry never armed. A timed-out or browser-blocked probe (Safari blocks mixed-content loopback fetches) is reported as inconclusive rather than asserted as "daemon down". Solves the chicken-and-egg where the inline dashboard banner can't load precisely when the redirect is down.

**DNS resolver** (`internal/dns/`) — Tiny UDP DNS server used on Windows (where there's no `/etc/resolver/` equivalent). Synthesizes `A=127.0.0.1` / empty AAAA for `*.<TLD>`; forwards everything else to upstream. Started by the daemon when `cfg.Daemon.DNS.Enabled`. Listens on 127.0.0.1:53. Off by default everywhere except Windows (set true by `vibe setup` on Windows). Has a fuzz test on the question-section parser.

**Cert** (`internal/cert/`) — Generates local ECDSA CA + leaf certs using Go stdlib. Per-OS trust install in `cert_<goos>.go`: macOS uses `security add-trusted-cert` into Keychain; Windows uses `certutil -addstore Root`. Leaf certs use explicit SANs per route (Chrome rejects `*.vibe` wildcards). `CAThumbprint` returns the SHA1 hex used by `certutil -delstore` for precise removal at uninstall (CN match would clobber unrelated certs sharing "local.vibe CA" as their name).

**winutil** (`internal/winutil/`, Windows only) — Small helpers shared between `cmd/` and `internal/daemon/`. `Sys32(name)` resolves a System32-shipped tool to its absolute path (never falls back to PATH lookup — a privilege-escalation surface during elevated setup). `PowerShellJSON(script)` runs Windows PowerShell with `-NoProfile -ExecutionPolicy Bypass` and returns stdout — used to talk to locale-invariant cmdlets (`Get-DnsClientServerAddress`, `Get-NetAdapter`) instead of screen-scraping localized netsh output. `TaskImageName(pid)` parses `tasklist /FO CSV` to recover an executable name for a PID.

**Config** (`internal/config/`) — Loads `~/.vibe/config.json`, falls back to defaults. Daemon port 7999, TLS port 7443 (disabled by default, enabled by `vibe setup`), TLD "vibe", log level "warn", dashboard view "list". `daemon.autostart` (pointer, default on) gates on-demand managed-route auto-spawn; absent key ⇒ enabled, so an omitted flag never reads as `false`.

**Agent skill** (`internal/vibeskill/`) — Embeds the canonical `SKILL.md` (`//go:embed`) and installs it at `<home>/.claude/skills/local-vibe/SKILL.md`, where Claude Code auto-discovers it in every session across all projects. The skill is deliberately lean: it steers agents away from guessing/hardcoding ports and localhost URLs and toward `vibe start` + `https://<name>.vibe`, then defers all detail to `curl http://localhost:7999/setup.md` rather than duplicating `setup.md`. `InstallTo(home)` / `UninstallFrom(home)` are OS-agnostic; `vibe setup` calls them from `setup_darwin.go` (real-user home via `realUserHome()` + chown, since setup runs as root) and `setup_windows.go` (plain `%USERPROFILE%`, user-integrity), gated by the `--no-skill` flag; `vibe uninstall` removes the dir. The **same SKILL.md** is checked into the repo's plugin-marketplace folder (`.claude-plugin/marketplace.json` + `plugins/local-vibe/`) so anyone can `/plugin marketplace add graiz/local.vibe` → `/plugin install local-vibe@vibe`. A test (`marketplace_test.go`) fails CI if the embedded and marketplace copies drift — re-sync with `cp internal/vibeskill/SKILL.md plugins/local-vibe/skills/local-vibe/SKILL.md`.

## Route types

Five route types with different lifecycle semantics:
- **sticky** — `vibe register`; persists across daemon restarts; reverse-proxied
- **pid** — API only; auto-removed when tracked PID dies
- **ttl** — `--ttl` flag on register; auto-expires after N seconds
- **managed** — `vibe start` (reads `vibe.json` or inline args); daemon manages the child process, dashboard has start/stop buttons. Port can be omitted for auto-assignment. Persists across daemon restarts and comes back up on its own: a surviving child is re-adopted, otherwise the route auto-spawns on first request (see `autostart.go`; opt out with `daemon.autostart=false`). Optional fields: `oauth_callback_port` (binds a localhost listener that 307-forwards to the .vibe URL — for OAuth providers that require a localhost redirect URI), `reserve_ports` (`{"name": port}` map of auxiliary ports the cmd also binds; reserved across the route table to prevent collisions, exposed to the child as `PORT_<UPPER_NAME>` env vars), `idle_timeout` (minutes; 0 = never auto-stop). Inside a git worktree, `vibe start` auto-registers `<branch-slug>.<app>` (dotted name, `Parent` field set) on a fresh port — see the worktree-routes pattern below.
- **bookmark** — External URL (e.g. Tailscale address); persists across restarts; visiting `name.vibe` either 307-redirects to the external URL or reverse-proxies to it (per-route `proxy` flag). Added/edited via dashboard modal.

## Key patterns

- **Event-based route lifecycle (no sweep):** There is no periodic route-monitoring goroutine. A managed child's death is detected the instant it happens — `cmd.Wait` for spawned children, a per-OS PID-exit watcher (`watchPIDExit`: kqueue/pidfd) for adopted and PID-tracked ones — and flips the route via `handleManagedExit`. TTL expiry and idle-timeout are per-route `time.AfterFunc` timers armed/canceled through `RouteTable` add/remove hooks. Instant death detection also removed the need for the old port-ownership "squatter" check, whose failure window only existed because the previous 5s poll let a dead PID get recycled before it was noticed. (The 500ms readiness probe below is a separate, bounded startup check, not a lifecycle poll.)
- **Route status:** Two separate fields — `Running` (process is alive) and `Ready` (port is accepting TCP connections). Managed routes start `Running=true, Ready=false`; a background goroutine polls the port every 500ms for up to 30s and flips `Ready=true` once the port responds. This handles REPL-wrapped servers where the process is alive before the HTTP server binds.
- **Dual communication:** Unix socket (preferred) with TCP fallback. Same HTTP mux serves both. On Windows the unix socket bind fails and we fall through to TCP-only — logged as a warning, daemon still starts.
- **Thread safety:** RouteTable uses RWMutex, ProcessManager uses Mutex.
- **Process trees, per-OS:** On darwin/linux, managed processes use `Setpgid: true` and SIGTERM to `-pgid` to kill entire process trees. On Windows, each managed child is wrapped in an anonymous Job Object with `KILL_ON_JOB_CLOSE`; `TerminateJobObject` is the moral equivalent of `kill(-pgid, SIGKILL)` (no SIGTERM-equivalent on Windows for arbitrary console children — termination is immediate, no flush window). Job assignment happens just after `cmd.Start()`, so descendants spawned in the sub-millisecond window before assignment escape the job; documented as a known limitation in `process_windows.go`.
- **Shell login, per-OS:** darwin spawns `$SHELL -lic` so managed processes get full PATH (nvm, Homebrew, etc.); linux uses `$SHELL -c`; Windows uses `cmd.exe /C` (via `%COMSPEC%`). Build-tag-gated in `process_<goos>.go` — never collapse into a shared codepath.
- **PID file safety:** Only written after successful TCP bind (tested in `daemon_test.go`).
- **Zero-downtime restarts:** `vibe dev` kills daemon → autostart hook restarts → persisted routes survive. macOS uses LaunchAgent; Windows uses Scheduled Task plus a rename-aside dance (Windows refuses to overwrite a running .exe).
- **Input validation:** Route names must match `[a-z0-9-]`, "local" is reserved. All user-supplied strings HTML-escaped in dashboard output to prevent XSS.
- **Cross-site protection on the API (`origin.go`):** the daemon API is unauthenticated and reachable from the browser (127.0.0.1:7999 and every `.vibe` host), and `handleRegister` executes `cmd` through a login shell — so without a guard, any web page could POST a `text/plain` body (a CORS simple request, no preflight to block it) and get **drive-by RCE**. `apiRequestCrossSite` therefore rejects state-changing requests (`apiStateChanging`: everything except GET, plus GET `/repair`, which rewrites a port) whose `Sec-Fetch-Site` is `cross-site` or whose `Origin` isn't ours. Trusted origins (`originTrusted`): `local.<tld>`, a registered **non-bookmark** route's host, and the daemon's loopback listeners — all of them subject to the same port test (`daemonPortTrusted`: the HTTP port, the TLS port when enabled, or portless i.e. the :80/:443 redirect). Applying that test to the `.vibe` branches too is load-bearing: every `*.vibe` name resolves to 127.0.0.1, so `http://local.vibe:31337` is whatever unrelated service holds that port, and such a page is schemefully *same-site* with the dashboard — `Sec-Fetch-Site` won't catch it. Ignoring the port there made any loopback port that renders attacker-influenced HTML a trusted API origin. **Bookmarks are excluded** — they proxy third-party sites onto a `.vibe` origin, which must never drive the API; managed/sticky routes are allowed because their pages are daemon-served and their children already run as the user. A *missing* Origin is trusted: browsers always send it on non-GET, so absence means a non-browser client (CLI, curl). Reads stay open — the daemon sends no CORS headers so cross-origin responses are unreadable, and the service worker's `/health` probe is cross-origin by construction. The check sits *after* the unknown-`/_api/`-path passthrough so proxied apps' own `/_api/` endpoints are unaffected.
- **Port auto-assignment:** Managed routes can omit `port` (or set to 0). `findFreePort(table)` scans 3000-3999, skipping ports claimed by existing routes, then falls back to OS assignment. The assigned port is injected as a `PORT` env var when spawning the child process and returned in the register API response. Persisted in `routes.json` so it survives daemon restarts.
- **Port conflict detection:** Before starting a managed process, verifies the port is free. If `killPort` fails to clear it, returns 409 with a clear error. Registering a route name that's already running returns 409 immediately. The `/ready` endpoint returns both `ready` and `running` so poll loops detect post-start crashes immediately.
- **Route icons:** Two fields — `Icon` (user-chosen emoji) and `AutoIcon` (auto-detected favicon as data URI). Display priority: Icon > AutoIcon > deterministic hash-based pool pick. Dashboard modal shows preview + emoji picker, never raw data URIs.
- **Dashboard view persistence:** List/grid toggle saved server-side via `PUT /_api/preferences` into `config.json`. Rendered server-side on page load — no flash of wrong view.
- **Embedded UI:** All HTML/CSS/JS is inline Go strings — no external assets, no build step. Dashboard includes a modal for CRUD operations on routes. Toast notifications surface errors from async actions.
- **TLS hot-reload:** Daemon holds a `sync.RWMutex`-guarded `*tls.Certificate` served via `GetCertificate`. When routes change (`saveStickyRoutes`), the leaf cert is regenerated with updated SANs and atomically swapped — no restart needed. The CA (10-year, trusted in Keychain on macOS / Windows root store on Windows) stays fixed; only the leaf (825-day) rotates.
- **Managed-route self-healing:** When a route's registered port stops answering, `routeRequest` serves the repair page (or the start page when the child is gone). Port discovery is per-OS: unix uses `lsof` on the process group; Windows enumerates Job Object members via `QueryInformationJobObject` and parses `netstat -ano`. A log-tail regex is the fallback on both. `RouteTable.UpdatePort` atomically rewrites the registration so subsequent requests proxy correctly. Start failures attach a tailed log + recovery hint (orphan PID, EADDRINUSE) via `StartError` → `Failure`; the start page surfaces a one-click "Kill PID X and Retry" button, and `safeKillPID` refuses to signal the daemon itself or other managed routes. That ownership test (`ProcessManager.OwnsPID`) matches **descendants**, not just the process-group leader vibe spawned: the leader is a login shell, so the process actually holding a route's port is usually a grandchild, and `lsof` reports that pid — a leader-only comparison let `killPort` SIGTERM another route's live dev server.
- **WebSocket upgrades and the dev-origin gate (`proxy_upgrade.go`):** Go's `ReverseProxy` tunnels upgrades natively, so HMR sockets work without special handling — the failure mode is one layer up. Dev servers increasingly gate their hot-reload socket on `Origin`: Next.js 15.2+ (`allowedDevOrigins`) answers an upgrade carrying a foreign Origin with **200 HTML instead of 101**. Behind vibe the Origin is always foreign (browser sends `https://<name>.vibe`; the server believes it is `localhost:<port>`), so the socket never establishes, the dev client retries, and after three failures calls `location.reload()` — a full page reload every ~20s that silently wipes client state and reads as an app bug. The Director therefore rewrites `Origin` to the upstream's own origin **on upgrade requests only**, preserving the browser's in `X-Forwarded-Origin`. The narrow scope is load-bearing: rewriting Origin on ordinary requests would break apps that check it for CSRF (Auth.js compares Origin against `AUTH_URL` on POST). Note the path is `_next/webpack-hmr` even under Turbopack. Bookmark routes rewrite Origin/Referer unconditionally instead (`proxy_bookmark.go`) — they force `Host` to the upstream too, so the whole request is same-origin from the upstream's view.
- **Proxy-failure recovery (no bare 502):** The reverse proxy for managed/sticky routes sets `proxy.ErrorHandler` → `handleProxyError`, so an upstream that fails — connection refused, or a squatter on a recycled ephemeral port that accepts TCP but doesn't speak HTTP — triggers `recoverManagedRoute` instead of surfacing an opaque 502. This is the runtime backstop for the case the pre-proxy guards can't catch: a reused PID makes `processAlive` true and a squatter makes `isPortReady`'s TCP dial true, so vibe would otherwise proxy into the stranger and 502. There are two ownership re-checks (process-group membership via `lsof`), both replacing the removed sweep-based `managedPortHealthy` check: (1) `handleProxyError`, which fires only on a failed upstream; and (2) `managedStrangerOnPort` on the healthy request path, which catches a squatter that *does* speak HTTP (so the proxy round-trip succeeds and the ErrorHandler never fires). The healthy-path probe is throttled (`managedOwnerCheckInterval`, 3s) and single-flighted (`ownerChecking` CAS) so a burst of parallel requests can't storm `lsof` — a recent healthy verdict short-circuits without shelling out. The `ErrorHandler` ignores `context.Canceled` (a client-aborted request is not an upstream failure).
- **Recovery is re-entrant, and must stay cheap:** `recoverManagedRoute` runs on every failed proxy round-trip, so it is reached constantly on a flaky upstream — not just after a daemon restart. Two consequences are baked in. `ProcessManager.Adopt` is idempotent: re-adopting a `(name, pid)` it already tracks returns immediately, because each call otherwise spawned another `watchPIDExit` goroutine holding another kqueue/pidfd that only closes when the process dies (unbounded growth against `RLIMIT_NOFILE`; one route on the author's machine logged 13+ re-adoptions). And a request that finds `isAutoStarting` true yields to the in-flight starter instead of clearing `Running` and re-entering the spawn path — otherwise a late request could stomp the winner's state, spawn a second time, and (once the first child bound its port) `preflightPort` → `killPort` the child it had just started. `endAutoStart` is deferred, since net/http recovers handler panics and a leaked guard wedges the route on a polling page for the daemon's lifetime.
- **Managed-route restart recovery (`autostart.go`):** After a daemon restart, managed routes come back up without a manual `vibe start`. The daemon persists each running managed route's process-group leader PID (`pid` in `routes.json`). On startup and on the next request to a stopped managed route, `recoverManagedRoute` tries, in order: (1) **adopt** a surviving child — `adoptOrphan` confirms the route's *registered* port is held by a member of the persisted PID's process group (unix-only; safe against squatters and against unrelated listeners a login shell spawns into the group, since it anchors on the registered port, not "whatever the group listens on"), then `ProcessManager.Adopt` records the PID so Stop/Deregister can kill it; (2) if a *foreign* process holds the port, serve the start page (never proxy to a stranger, never spawn on top of it); (3) **auto-spawn** on a free port via `startManagedNow` (which preflights the port like `handleStart`) and serve the reconnecting page; (4) else the start page. The crash-loop guard skips auto-spawn when a `Failure` is already recorded. A `beginAutoStart`/`isAutoStarting` guard de-dupes concurrent requests and keeps the reconnecting page polling instead of declaring the route dead mid-spawn. Windows never adopts (Job Objects kill children on daemon exit) — it relies on auto-spawn. Gated by `daemon.autostart` (default on); adoption always runs.
- **Browser-form vs JSON requests:** Some `/_api/routes/*` handlers (`handleStart`, `handleStop`, etc.) 303-redirect back to the dashboard when the request looks like a browser HTML form post — detected via `isBrowserFormRequest` (Content-Type `application/x-www-form-urlencoded`). The CLI client sends `Accept: application/json` and gets the JSON response directly. Don't gate the redirect on the `Accept` header alone: a missing Accept used to be misclassified as a browser request, and the resulting 303 to `https://local.vibe/` killed the CLI when followed over the Unix-socket transport (TLS over unix conn fails, surfaced as a spurious "daemon not running").
- **Worktree routes:** a managed route named `<worktree>.<app>` with `Parent` set (`internal/daemon/worktree.go`). `vibe start` in a linked worktree detects it (`cmd/worktree.go`, `--git-dir` ≠ `--git-common-dir`), slugs the branch name, and registers the dotted route; the daemon forces port auto-assign, reassigns `reserve_ports` values, rejects `oauth_callback_port`, and defaults `idle_timeout` to 60m. Routing is the normal map hit (dotted names are ordinary keys); a missing worktree host whose parent is known 307s to `<app>.vibe` (never 301 — reused branch names). Worktree-gone pruning is touch-based and runs on load, request-recovery, start, AND the healthy proxy path (one stat per request — a running child outlives a removed worktree and would serve stale content forever): "gone" (`dirIsGoneWorktree`) means the `Dir/.git` link is absent **and the containing directory is readable** (covers deleted dirs and leftover folders whose worktree was `git worktree remove`d — file-sync can resurrect the dir). The parent-directory condition distinguishes a removed worktree from an unmounted or still-syncing volume: this repo lives on a file-sync mount and the daemon starts at login, so a bare ENOENT check would deregister every worktree route and kill its server on any reboot that races the mount. Load-time pruning also kills a surviving child via its persisted PID (`killAdoptedProcess`) — but only when `pidGroupHoldsPort` proves that pid's group still holds the route's registered port, the same evidence `adoptOrphan` demands. A pid alone is not identity across daemon downtime (the OS recycles them) and the kill hits a whole group; the check also targets the kill better, since a process that isn't listening isn't serving the stale content the prune exists to stop. `vibe.json` sync for worktrees imports `cmd` only. The start page doubles as the picker: it lists registered sibling worktrees AND unregistered on-disk ones (`discoverUnregisteredWorktrees` shells out to `git worktree list` via `internal/gitwt` — off the hot path, only on picker render/recovery), each discovered row register-and-starts via `POST /_api/routes/{app}/worktrees` (path must match a discovered worktree; inherits the parent's cmd). Any existing worktree suppresses the parent's on-demand auto-start (`hasWorktrees` gate in `recoverManagedRoute`) so the visitor chooses instead of main silently respawning; the dashboard groups registered ones under the parent. `gitwt.Slugify` strips the agent harness's `worktree-` branch prefix for shorter URLs. TLS SANs and DNS needed zero changes. **Worktree OAuth** (`oauth_worktree.go`): worktrees inherit the parent's `oauth_callback_port` bridge — the proxy's `ModifyResponse` tags outbound authorize redirects' `state` with the route name (`v1!<route>!<orig>`, synthetic state injected for PKCE-only flows like Auth.js v5 Google), and `handleOAuthCallbackBridge` unwraps it and forwards the callback to that worktree's origin (guarded: only worktrees of the bridge's owner; synthetic states are stripped). Requires the app to build its redirect URI from fixed config (`AUTH_URL`), not its port; client-side-assembled provider URLs can't be tagged. `prepareWorktreeEnv` copies the parent's untracked `.env*` into a worktree before spawn (never overwrites).
- **Bookmark proxy mode:** When a bookmark has `proxy=true`, `proxyBookmark` reverse-proxies to the upstream instead of 307-redirecting. The upstream `Host` header is forced to the external URL's host (SNI/vhost correctness). Same-origin 3xx `Location` headers are rewritten to the `.vibe` host, `Domain=` is stripped from `Set-Cookie` so browsers actually store cookies, and `X-Forwarded-For` is suppressed (strict upstreams like Home Assistant return 400 when they see it). The bookmark URL's path is treated as a landing destination: requests to `name.vibe/` 302 once to the path, but everything else passes through at the origin so SPA assets loaded from `/` resolve correctly. Optional per-route `insecure_skip_verify` disables upstream TLS verification for self-signed targets (Tailscale MagicDNS, etc.).

## System setup

### macOS (`cmd/setup_darwin.go`)

`sudo vibe setup` installs: dnsmasq, `/etc/resolver/vibe`, the pf anchor + `/etc/pf.conf` reference and the `com.vibe.pf` LaunchDaemon (80 and 443 → the daemon's configured HTTP/TLS ports, default 7999/7443), TLS certificates (local CA + leaf, trusted in macOS Keychain), enables TLS in config, user LaunchAgent (daemon at login), and the global agent skill (`~/.claude/skills/local-vibe`, unless `--no-skill`). De-escalates brew/launchctl ops via `SUDO_USER` (the skill install writes to the real user's home and chowns it back). `vibe uninstall` reverses every step.

**pf redirect resilience (`cmd/pf_darwin.go`):** vibe's two rdr rules live in their **own pf anchor** (`/etc/pf.anchors/com.vibe`), referenced from `/etc/pf.conf` by an `rdr-anchor "com.vibe"` line in the translation section and a `load anchor` line at the end. **Never load them as a replacement main ruleset** (`pfctl -ef -`): that detaches Apple's `com.apple/*` anchors — silently disabling the Application Firewall, AirDrop and Internet Sharing — and gets wiped by anything that reloads `/etc/pf.conf` (VPN clients, Internet Sharing / vmnet backing Docker Desktop and VMs, macOS updates, the boot race with `com.apple.pfctl`). With the anchor those same reloads *re-install* vibe's rules. This also removed the ruleset-merging machinery this file used to carry (capture `-sn`/`-sr`, bucket by section, re-emit): vibe no longer owns the main ruleset, so there is nothing to merge.

The `com.vibe.pf` LaunchDaemon runs the hidden `vibe pf-apply` at boot (`RunAtLoad`) **and on every network change** (`WatchPaths` on resolv.conf — fires on VPN up/down), because an anchor survives a pf.conf *reload* but not a `pfctl -F` flush or a VPN that loads its own ruleset. `pf-apply` is idempotent. Each run: rewrites the anchor file with the configured ports (so a `config.json` port change takes effect without re-running setup); **re-patches `/etc/pf.conf` if the lines are missing** — it is a system file a macOS update can replace wholesale, and re-patching is what lets `vibe doctor --fix` recover from that; then checks **two independent** things and repairs each on its own — whether the main ruleset still *calls* the anchor (`pfctl -s nat` contains `rdr-anchor "com.vibe"`) and whether the anchor still *contains* our current rdr rules (`pfctl -a com.vibe -s nat`); and enables pf only when disabled (`pfctl -E` increments an enable refcount per call, which a per-network-change trigger would climb indefinitely). The ports arrive as `--http-port`/`--tls-port` flags — baked into the plist by `vibe setup` from the real user's config and passed again by `doctor --fix` — because pf-apply runs as root, where reading the config would find *root's* home. `patchPFConf` places the `rdr-anchor` after the last translation line, else before the first filter line, never blindly at EOF: pf rejects a file whose translation rules follow filter rules, and an EOF append silently produces exactly that on a custom pf.conf. The patched file is vetted with `pfctl -n -f` on a temp file before an atomic rename, so a bad config can never break boot-time pf loads; an unpatchable custom pf.conf degrades to a printed instruction rather than a failed setup. Those two checks must stay independent (not `if`/`else if`): a `pfctl -F all` breaks only the *call* — anchor contents survive a flush, so every other check still reads healthy — while a `config.json` port change breaks only the *contents*. Repairing the call means reloading `/etc/pf.conf`, which replaces the whole main ruleset; that is unavoidable (an anchor call can only be added by reloading the ruleset containing it) and is the one operation here that can disturb a coexisting pf user, so it is gated on pf.conf actually carrying our lines — otherwise the reload cannot install the reference and would just clobber the live ruleset on every network change forever — and it is announced on stderr so it shows up in the `com.vibe.pf` log. That disturbance is real and has been observed, not just reasoned about: services that insert anchors into the live ruleset at runtime (ExpressVPN's kill-switch installs an `xvpn/*` tree; pf.conf's own header warns that system services do this) are named nowhere in the file, so a reload drops their anchor *calls* and leaves their rules loaded but unevaluated — on a test machine ExpressVPN's `xvpn` call disappeared from the filter section across one reload and its daemon re-installed it unprompted seconds later. Expect exactly that shape: we disturb a coexisting pf user, a well-behaved one recovers itself. The reverse also holds — a reload re-runs *every* `load anchor` directive in pf.conf, including other tools', so a stale third-party anchor file can be brought back to life by our repair. Loading the anchor alone never disturbs anyone and runs unconditionally when its rules are stale. Uninstall flushes the anchor, removes the file, strips the two lines, and reloads. Known gap: if the VPN's kill-switch *blocks/route-to's* loopback (not just flushes pf), the rules are present but the redirect can still be intercepted — that's a VPN "allow LAN access" setting, not a vibe bug. Event-driven, no polling.

**`vibe doctor` (`cmd/doctor.go`):** Diagnoses each layer of the request path — daemon reachable (via the client: unix socket → TCP), HTTP/TLS listeners, DNS resolves `*.vibe`, the privileged-port redirect (a loopback dial to :80/:443, the layer a VPN breaks), and cert presence. `vibe doctor --fix` repairs the redirect by re-running `pf-apply` via sudo (per-OS hook: `doctor_darwin.go` / `doctor_other.go`). The redirect probe (shared `internal/netprobe`) needs no root; it's also surfaced as a `vibe list`/`vibe status` warning and the service-worker fallback page. That CLI warning probes **both** privileged ports and names which one is down — a partial ruleset can leave one rdr live and the other missing, and probing only :80 stayed silent while every `https://*.vibe` was broken. It also runs the daemon-reachability check first, so a merely-stopped daemon (whose rdr forwards to a closed port) isn't misreported as a broken redirect. `vibe dev` restarts the daemon deterministically with `launchctl kickstart -k` (avoids launchd's ~10s respawn throttle) and confirms readiness via the client transport, not a raw TCP-7999 dial.

### Windows (`cmd/setup_windows.go`)

`vibe setup` (from elevated PowerShell) installs: TLS cert + CA trust via `certutil -addstore Root`, `netsh portproxy` rules for 80→7999 and 443→7443, repoints every connected adapter's DNS to 127.0.0.1, enables TLS + DNS in config, registers a Scheduled Task `vibe` triggered on logon at the user's normal (medium) integrity level, and installs the global agent skill (`~/.claude/skills/local-vibe`, unless `--no-skill`) — the daemon's runtime ops are all unprivileged on Windows (binding low ports doesn't require admin, unlike POSIX), so dev servers and dashboard handlers don't inherit Administrator. `precheckPortCollisions` runs before any state change: if UDP :53 is held (Acrylic, NextDNS, Pi-hole, ICS), the offender is named via `netstat` + `tasklist` and the user can abort cleanly.

DNS-snapshot safety: `backupAdapterDNS` writes `~/.vibe/dns-backup.json` *before* repointing adapters and preserves an existing snapshot on re-setup (so the *first* pre-vibe state is what gets restored). `stripLoopbackServers` filters 127.x.x.x at snapshot time AND at restore time, then `verifyAndFixLoopbackDNS` does a final post-restore pass forcing DHCP on any adapter still pointing at the removed listener — three independent layers of defense against ending up with a dead resolver.

Cert removal at uninstall matches by SHA1 thumbprint (`cert.CAThumbprint`), not Subject CN — CN match would clobber unrelated certs sharing "local.vibe CA" as their name.

`vibe uninstall` reverses every step.
