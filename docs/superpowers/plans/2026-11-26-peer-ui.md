# Peer Management in the Dashboard — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Manage peers entirely from the dashboard — enable/disable at runtime, show a code, discover and pair, edit, remove — on top of a hardened pairing code.

**Architecture:** Pairing hardening lives in `internal/peer` (code format, PBKDF2-stretched proof, short key). The daemon gains a runtime peers switch (atomic flag + start/stop of listener and sync loop), a `/peer/hello` endpoint, a probe/classifier, a discovery sweep (local subnets + Tailscale), and a peer edit endpoint. The dashboard's Peers section is rebuilt on the existing `PeerAdmin` modal.

**Tech Stack:** Go 1.22 floor, stdlib only (+ existing Cobra, x/sys); `html/template` dashboard with inline JS (`templates/pages.js` helpers `vibeAPI`, `showToast`, `reloadSoon`).

**Spec:** `docs/superpowers/specs/2026-11-26-peer-ui-design.md`

## Global Constraints

- No new dependencies; `go.mod` stays `go 1.22` (so no `crypto/pbkdf2` import outside a `go1.24`-tagged test).
- Pairing code: 8 chars, `XXXX-XXXX`, Crockford base32 alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`, at least one digit per block.
- Proof salt prefix: `vibe-peer-pair-v2|`; PBKDF2-HMAC-SHA256, iterations tuned to ~100 ms on a current Mac.
- Short key: first 8 hex chars of the SHA-256 fingerprint, uppercased, shown `4F2A·91C3`.
- Every new `/_api` endpoint: dashboard/CLI only — never `ownRoute`; state changes are POST/PUT; `discover`/`probe` also `localOnly`.
- `/peer/hello` returns only `{"name", "code_open"}`.
- Sweep: private IPv4 (RFC 1918) only, never 100.64.0.0/10 or link-local, skip subnets > 1024 addresses, on demand only, ~3 s overall deadline.
- Listener runs only while peers exist or a code is open.
- Untrusted names (from `/peer/hello`, Tailscale) pass through `peer.SanitizeName` and render via `textContent`.
- Commits: CLAUDE.md forbids committing unless the maintainer asks — each task ends at a checkpoint, not a commit.
- Workflow: after each task `go build ./... && go vet ./... && go test ./...`; `GOOS=windows go vet ./...` and `GOOS=linux go vet ./...` before the final task. Never `git add -A`; check `git status` for unexpected staged files (the repo syncs across machines) and `git reset -q` the index if needed.

## Review Focus

1. A user types the code lowercase, without the dash, or with O/I/L for 0/1 → it pairs (Task 1 test `TestNormalizeCode`).
2. One machine updated, the other not → pairing fails with "make sure both machines run the same vibe version", not a bare 403 (Task 1 test `TestPairWithOldResponderSaysUpdate`).
3. Peers turned off while a relay request is mid-flight or a code is open → connection cut, code closed, nothing still listening (Task 2 test `TestDisablePeersTearsDown`).
4. A host on the LAN accepts TCP on 7444 but never speaks TLS → the probe returns `none` within its deadline, the picker doesn't hang (Task 3 test `TestProbeStalledHostTimesOut`).
5. A peer or Tailscale node reports a name containing markup or spaces → it is sanitized before reaching the dashboard (Task 3 test `TestProbeSanitizesName`).
